# Session Archive: Fix Standalone Missing DLL and Video Rendering Alpha Discard

- **Session Version**: v4.11
- **Date**: 2026-10-25
- **Context**: Diagnosing and resolving the `msys-stdc++-6.dll` missing error in Option A standalone packages, and resolving the invisible intro video playback bug.

---

### User Input
```text
1. running the game with Option A gives "main.exe - System Error The code execution cannot proceed because msys-stdc++-6.dll was not found. Reinstalling the program may fix this problem."
2. The intro video is not showing anything visually. Only audio keeps playing.
```

### AI Thinking & Planning Summary
> The user identified two critical issues:
> 1. Running the packaged distribution (Option A) produced a Windows system dialog: `msys-stdc++-6.dll was not found`.
> 2. The intro video played audio, but rendered completely invisible on screen.
>
> 1. **Root Cause Analysis — Missing `msys-stdc++-6.dll`**:
>    - Inspected PE import tables via `objdump -p build/main.exe`.
>    - The MSYS2 `g++` compiler defaults to dynamic linkage of standard C++ runtime libraries (`msys-stdc++-6.dll` and `msys-gcc_s-seh-1.dll`). When extracted and run on a machine without MSYS2 in system PATH, the Windows dynamic linker halts with the system dialog.
>    - *Solution*:
>      - Added `-static-libgcc -static-libstdc++` to the `g++` command in [`Makefile`](/Makefile), baking the standard C++ library directly into the executable.
>      - Updated the `package` target to bundle `msys-2.0.dll` alongside `glfw3.dll` and `assets/`. Verified via `objdump` that `msys-stdc++-6.dll` is completely eliminated from the import table.
>
> 2. **Root Cause Analysis — Invisible Intro Video Visuals**:
>    - Created diagnostic tool [`scratch/diag_video.cpp`](/scratch/diag_video.cpp) to inspect decoded `IMFSourceReader` frame samples.
>    - *Discovery*: Windows Media Foundation's `MFVideoFormat_RGB32` provides 32-bit quad-bytes $[B, G, R, X]$, where the reserved 4th byte $X$ is strictly `0x00`. Out of 2,088,960 pixels per frame, all 2,088,960 had an alpha byte of 0!
>    - The engine's fragment shader in [`src/Renderer.cpp`](/src/Renderer.cpp) previously contained:
>      `if (texColor.a < 0.12) discard;`
>      Because $a = 0.0 < 0.12$, the GPU discarded $100\%$ of all pixels across every single video frame, resulting in an entirely invisible video while audio played.
>    - *Solution*:
>      1. **Shader Alpha Flag**: Introduced `uniform bool uDiscardAlpha;` to the fragment shader in [`src/Renderer.cpp`](/src/Renderer.cpp) and [`include/Renderer.h`](/include/Renderer.h). Defaulted to `true` for game sprites and tiles, and set to `false` for opaque video frame rendering.
>      2. **Texture Swizzle & Format**: In [`src/VideoPlayer.cpp`](/src/VideoPlayer.cpp), configured `glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_SWIZZLE_A, GL_ONE)` and used `GL_RGB` internal format, forcing texture fetches to treat alpha as `1.0`.
>      3. **Viewport Dynamic Bounds**: In [`src/main.cpp`](/src/main.cpp), queried real framebuffer dimensions via `glfwGetFramebufferSize` to initialize `glViewport` and dynamically scale letterboxed 16:9 quads.
>
> 3. **Verification**:
>    - Compiled with `mingw32-make` and verified 0 warnings, 0 errors.
>    - Checked `objdump -p build/main.exe` and confirmed `msys-stdc++-6.dll` was removed.
>    - Tested `build/main.exe` launch with video rendering active.
>    - Re-packaged and verified `TheWenderer_Standalone.zip`.
>    - Synchronized [`README.md`](/README.md), [`doc/changelog.md`](/doc/changelog.md), and [`doc/LEARNING_GUIDE.md`](/doc/LEARNING_GUIDE.md).
