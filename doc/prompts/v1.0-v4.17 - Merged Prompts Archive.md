- **Session Version**: v1.0

- **Context**: Project explanation, guided documentation generation, and complete Phase 1 implementation of The Wenderer endless runner.

---

### High-Level Architectural Rationale & Design Decisions
> 1. Analyzed the project proposal, research analysis, and implementation roadmap. The core novelty is "Wending"—sudden 90-degree orthogonal shifts in running direction paired with a smoothly rotating camera follow.
> 2. Replaced multi-triangle hardcoded geometry with a single reusable 1x1 Quad VAO/VBO transformed via Model-View-Projection (MVP) matrices in GLSL, significantly reducing memory and draw call overhead.
> 3. Modeled track segments as vector-oriented lines and bounding areas. At the end of each segment, direction indices cycle, invoking `glm::mix` to interpolate camera rotation over ~0.45 seconds.
> 4. Structured collision detection using Axis-Aligned Bounding Box (AABB) checks evaluated against active obstacle arrays each frame.
> 5. Bundled GLFW, GLAD, and GLM libraries locally to make compilation completely independent and self-contained with zero external installation friction.

## Side-View Endless Runner Transition with Dynamic Direction and Sprites - v3.0

- **Session Version**: v3.0
- **Date**: 2026-10-24
- **Context**: Transition from top-down 2D runner to side-view endless platformer, pulling animated LPC character sprite sheet from the internet, and implementing autonomous dynamic direction shifting in random intervals.

---

### User Input
```text
the game should be side-view endless runner and platformer instead of top-down view. Alongside that major change, implement the following:
- Pull a basic running (right and left), climbing, falling, animation sprite from the internet.
- The scope of the game suggests that the direction will frequently change (for now, without any prior trigger) in random intervals (not too long). The sprite animation should change accordingly to show the corresponding direction movement.
```

### High-Level Architectural Rationale & Design Decisions
> 1. **Perspective Shift (Top-Down to Side-View 2D Platformer)**:
>    - Migrated the world coordinate system to an orthographic side-view: horizontal axis ($X$) represents running progression (both positive and negative), while the vertical axis ($Y$) represents elevation, platform heights, ladders, and gravitational acceleration.
>    - Implemented a standard delta-time physics model with constant downward gravity ($g = -32.0\,\text{m/s}^2$), vertical velocity clamping, AABB ground/platform surface landing resolution, and pitfall abyss detection.
>
> 2. **Modern OpenGL 3.3 Texture Mapping & Dynamic UV Sub-Rect Slicing**:
>    - Extended the vertex structure to include 2D texture coordinates (`vec2 aTexCoord`), keeping a single unified $1 \times 1$ reusable quad in GPU VRAM.
>    - Integrated `stb_image.h` for native PNG decoding.
>    - Added a uniform sub-rect `uUVRect = (u, v, du, dv)` to the vertex shader, computing exact sub-textures on the GPU on the fly with zero CPU vertex buffer reallocation.
>
> 3. **Internet-Sourced Animated Character Sprites (Liberated Pixel Cup)**:
>    - Downloaded and composited open-source character sprites (Liberated Pixel Cup, CC-BY-SA 3.0 / GPL 3.0) into `assets/player_sheet.png`.
>    - Mapped distinct animation states:
>      - **Running Right**: Row 37 (8 frames, 12 FPS)
>      - **Running Left**: Row 35 (8 frames, 12 FPS)
>      - **Climbing**: Row 30 (6 frames, 10 FPS)
>      - **Falling**: Row 26, Frame 3 (in-air downward fall posture)
>      - **Jumping**: Row 26, Frame 1 (rising jump frame)
>
> 4. **Autonomous Dynamic Direction Shifts (Random Intervals)**:
>    - Implemented a timer-based state machine that randomly selects interval durations between 3.0 and 6.0 seconds.
>    - Upon expiration, the autonomous movement direction dynamically switches ($\text{DIR\_RIGHT} \longleftrightarrow \text{DIR\_LEFT}$ or triggers vertical ladder climbing), updating the animation, reframing the side-view camera look-ahead, and flashing a user-facing visual alert banner.

### High-Level Architectural Rationale & Design Decisions
> 1. **Brackeys 2D Platformer Asset Integration**:
>    - Downloaded official pixel art assets from the Brackeys platformer bundle (`First Game/assets/sprites/`):
>      - [`/assets/world_tileset.png`](/assets/world_tileset.png) ($256 \times 256$, $16 \times 16$ tile grid): Provides grass surface caps, inner dirt fill, climbable ladders, and hazardous spikes.
>      - [`/assets/platforms.png`](/assets/platforms.png) ($64 \times 64$): Grass, snow, sand, and stone platform slabs.
>      - [`/assets/coin.png`](/assets/coin.png) ($192 \times 16$): 12-frame rotating gold coin animations.
>      - [`/assets/fruit.png`](/assets/fruit.png) ($64 \times 64$): 4 fruit types utilized as Mystery Direction Relics.
>    - Replaced generic solid-color shape drawing with multi-texture binding in the Modern OpenGL pipeline (`drawQuad(texID, ...)`).
>
> 2. **Direction-Shift Mystery Relics**:
>    - Implemented `DirectionRelic` entities spawned along elevated runways using the fruit sprite atlas.
>    - When the player's AABB overlaps a relic:
>      - Picks an entirely random direction uniformly from `[DIR_RIGHT, DIR_LEFT, DIR_UP, DIR_DOWN]`.
>      - Flashes a high-visibility on-screen banner for 2.4 seconds (e.g., `[MYSTERY RELIC: DIRECTION SHIFT: UP (CLIMB)]`).
>      - Relic is consumed and awards $+150$ bonus score.
>
> 3. **Vertical Movement Mechanics (Ladders & Pitfalls)**:
>    - **Ladders**: Inter-tier wooden ladders (sliced from `world_tileset.png` tiles $(9,3)$ and $(9,4)$) span between Ground ($Y = -3.5$), Middle ($Y = -0.4$), and Upper ($Y = +2.6$) tiers. When within ladder bounds, gravitational fall is paused and the player climbs upward/downward using `W`/Up, `S`/Down, or autonomous vertical states.
>    - **Pitfalls & One-Way Platforms**:
>      - Elevated platforms are one-way (`isOneWay = true`): players land cleanly on top, but pressing `S` / Down enables dropping down through platforms.
>      - Procedural level chunks feature deliberate pitfall gaps that let players drop safely down into lower corridors.
>
> 4. **Abyss Immunity (No Out-of-Bounds Deaths)**:
>    - Eliminated all out-of-bounds fall deaths.
>    - Implemented a continuous Bedrock Ground level at $Y = -3.5$ textured with grass caps and dirt blocks. Falling off any high platform safely lands the player on lower platforms or the bedrock ground floor.
>
> 5. **Lethal Spiky Traps & Game Over**:
>    - With abyss deaths removed, primary lethal hazard is shifted to **Spiky Traps** (`SpikeTrap`), mapped to tile $(4, 8)$ in `world_tileset.png`.
>    - Spikes are positioned inside pit bottoms and platform edges. Touching or falling onto any spike detects an AABB overlap, triggers the `DEAD_IMPALED` state, and displays the Game Over screen with distance and score.

## Tunnels Slopes Audio SFX Dynamic Endless Platforms and Corner HUD - v3.2

- **Session Version**: v3.2
- **Date**: 2026-10-24
- **Context**: Implementing vertical ladder tunnel shafts, steep slide slopes for downward traversal, Windows Multimedia (WinMM) in-memory procedural audio synthesis, dynamic endless random platform generation, environment biomes with transition phase, and comprehensible corner HUD notification cards.

---

### User Input
```text
there are no way to go up and down. Make tunnel-like path that shows when we try to climb to a ladder. add movement sfx. Make the collectibles comprehensible (add corner captions when I collect something to show briefly).
```

### High-Level Architectural Rationale & Design Decisions
> 1. **Vertical Ladder Tunnel Shafts & Automatic Centering**:
>    - Encased ladders within masonry-walled vertical shafts (`worldTunnels`). Left and right stone columns border the shaft, enclosing a dark shadowed shaftway backdrop with an illuminated emerald guide line.
>    - When near or entering a ladder tunnel, the player's horizontal coordinate smoothly snaps to the shaft centerline (`glm::mix(playerPos.x, tunnel.x, dt * 10.0f)`), disabling gravity and enabling upward/downward traversal (`W`/Up and `S`/Down) with animated climbing cycles.
>
> 2. **Steep Slopes for High-Speed Downward Traversal**:
>    - Introduced angled slope ramps (`worldSlopes`) connecting high platforms to lower levels.
>    - Stepping onto a slope activates the `isSliding` state:
>      - Player coordinates are locked to the angled surface $Y_{\text{surf}}(x) = Y_1 + \frac{x - x_1}{x_2 - x_1} \cdot (Y_2 - Y_1)$.
>      - Downward acceleration increases to $11.5\,\text{m/s}$.
>      - Character sprite tilts along the slope angle $\theta$.
>      - Continuous rushing slide audio plays while sliding.
>      - Exiting the slope launches the player with momentum onto the lower level.
>
> 3. **Zero-Dependency Procedural Audio Engine (`winmm`)**:
>    - Sourced no external audio files; synthesized 16-bit mono PCM samples at 22,050 Hz directly in memory via RIFF/WAVE header assembly.
>    - Integrated standard Windows Multimedia `PlaySoundA(..., SND_MEMORY | SND_ASYNC)`.
>    - Procedural sound palette: Footsteps (`SFX_STEP`), Jump (`SFX_JUMP`), Ladder climb clacks (`SFX_CLIMB`), Slope slide whoosh (`SFX_SLIDE`), Gold coin chimes (`SFX_COIN`), Relic arpeggios (`SFX_RELIC`), Direction shift warp (`SFX_SHIFT`), and Spike impalement crunch (`SFX_DEATH`).
>
> 4. **Dynamic Endless Procedural Platforms**:
>    - Procedural chunk generation assembles randomized multi-elevation platforms (`-0.6`, `1.2`, `2.8`), randomized lengths ($4$ to $9$ tiles), randomized gap widths ($3.2$ to $7.0$ units), ladder tunnels, steep slopes, coin clusters, and spiky pits.
>    - Dynamically streams forward and backward as the player turns and traverses, pruning distant chunks past 80 units for bounded memory and infinite runtime.
>
> 5. **Dynamic Biomes & Cinematic Transition Phase**:
>    - 4 environmental themes: Emerald Forest, Frozen Glacier, Sunset Canyon, Mystic Cavern.
>    - Direction changes trigger a transition phase: brief time dilation ($0.45\times$ speed for $0.25$s), screen flash, and smooth color interpolation of sky, pillars, and platform tints.
>
> 6. **Comprehensible Corner HUD Notifications**:
>    - Top-left glassmorphism card displaying the rotating item icon (spinning gold coin or fruit relic), category tag, title, and descriptive impact text for $2.8$ seconds with slide-in and fade-out animations.

> 2. > ---
>
> **Issue 2: Leftward Movement Analysis**
>
> Deep code analysis of [`src/World.cpp`](/src/World.cpp) `World::updateProcedural()` confirmed that the world IS procedurally generated in **both** directions:
> - **Rightward**: `if (playerX + 35 > rightGenEdge)` triggers a new 35-unit chunk to the right.
> - **Leftward**: `if (playerX - 35 < leftGenEdge)` triggers a new 35-unit chunk to the left.
>
> Both directions use the **identical** `generateChunk()` function, which procedurally spawns bedrock, surface ground, cavern floors, elevated platforms, ladder tunnel shafts, steep slopes, spikes, relics, and coins. There is zero difference in the code path for left vs. right generation.
>
> **Why it might appear non-endless leftward**:
> - The initial chunk (`-25` to `35`, `isInitial = true`) returns early after placing only bedrock/surface/cavern tiles. The leftward stretch from `-25` to `0` has basic terrain but no platforms, ladders, relics, or slopes.
> - When the player starts at $X = 0$ and the default direction is `DIR_RIGHT`, leftward generation fires immediately (since $0 - 35 = -35 < -25$), generating a fully featured chunk from $-60$ to $-25$.
> - However, many players never manually turn left (pressing `A`) and may perceive the world as right-only. In reality, every time the player moves close enough to the left edge, another procedural chunk is generated — the world is infinite in both directions.
>
> **Static vs. Random Resource Usage**:
> - A **static (pre-generated) level** occupies fixed memory proportional to the entire level length. If the level were 10,000 tiles long, all tiles, objects, and collision data would exist in memory at all times.
> - The current **procedural (random) generation** creates chunks only when needed (within 35 units of the player) and **garbage collects** objects beyond 85 units behind the player (`std::remove_if` on every entity vector).
> - **Result**: Procedural generation uses far less memory for infinite worlds — only ~170 units of world data exist in memory at any moment, regardless of how far the player has traveled. Static generation for an infinite world would be impossible (infinite memory), and for a finite world would use more memory than needed since distant tiles would still be stored.

## Circular Energy Shield Bubble and Single-Hit Trap Absorption - v4.16

- **Session Version**: v4.16
- **Date**: 2026-10-25
- **Context**: Eliminating repeated "deflected" spam by removing equipped shield on first hazard contact with post-hit grace invulnerability, and upgrading shield rendering from a square quad to an anti-aliased analytical circular force-field bubble.

---

### User Input
```text
the shield equiped by picking up the fruits should get removed upon first hit by the trap. Instead it shows "deflected" message continuously and repeatedly until the shield duration is finished. Also, make the shield circular and wrapped around the player instead of a big box that is currently used.
```

### AI Technical Analysis & Implementation Strategy
1. **Deflection Loop Analysis**:
   - *Problem*: In `src/main.cpp`, collecting fruits granted a 10-second `shieldTimer = 10.0f`. When colliding with platformer spiky traps (`gameWorld.spikes`), ladder climb traps, or sky-fall raptors/mines, the code checked `if (shieldTimer > 0.0f)` and triggered `AudioManager::play(SFX_SLIDE)` plus floating `"DEFLECTED!"` text, but never cleared or reduced `shieldTimer`. Because the player intersects the trap over dozens of consecutive physics frames, this produced continuous visual and audio spam until the 10-second timer expired.
   - *Single-Hit Removal*: The shield must break on the very first frame of trap contact (`shieldTimer = 0.0f`).
   - *Grace Invulnerability Window*: If `shieldTimer` is simply set to `0.0f` without protection, the player character remains physically overlapping the hazard hitbox on frame 2 (16ms later), causing instant death immediately after deflection. To guarantee fairness, a post-hit grace invulnerability window (`postHitInvulnTimer = 0.75f`) is applied immediately upon shield shatter. While `postHitInvulnTimer > 0.0f`, hazards pass without inflicting damage or triggering death.
   - *Feedback Notification*: Replaced the repetitive spam with a single clear announcement: `"SHIELD BROKE! [TRAP DEFLECTED]"` with a single audio cue.

2. **Analytical Circular Shader Architecture**:
   - *Eliminated Square Box*: The previous shield rendered two flat square quads scaled at $2.4\times 2.4$ and $2.6\times 2.6$.
   - *Mathematical Circle in Fragment Shader*: Instead of tessellating high-polygon triangle fans on the CPU, circle rendering was integrated directly into the core shader pipeline (`Renderer::drawCircle` in `src/Renderer.cpp`).
   - *Shader Math*:
     - Normalized coordinates from center: $\vec{p} = \text{TexCoord} - (0.5, 0.5)$.
     - Euclidean distance: $d = \|\vec{p}\|$.
     - Fragments with $d > 0.5$ are discarded via `discard;`.
     - Anti-aliased outer perimeter via smooth hermite interpolation: $\alpha_{\text{edge}} = 1.0 - \text{smoothstep}(0.482, 0.50, d)$.
     - Glowing rim power curve: $\text{rim} = (2d)^{\text{uRimPower}}$, producing a translucent core wrapped in an intense, pulsating force-field rim.
   - *Hero Wrapping*: Uniformly integrated across all 3 game scenes (Platformer Runner, Ladder Climb, Sky-Fall Diving) with gentle breathing oscillation ($\sin(8t) \times 0.06$).

## Ladder Hero Scale Fix, Post-Intro Tutorial Modal, Shield Pickup Icon, and Scene Exit Timers - v4.17

- **Session Version**: v4.17
- **Date**: 2026-10-25
- **Context**: Resolving miniature ladder sprite rendering, adding post-intro tutorial dialog with Pause Menu review, replacing ambiguous fruit items with dedicated shield pickup icons, and adding mini-game countdown timers with exit appearance announcements.

---

### AI Technical Analysis & Implementation Strategy
1. **Ladder Climbing Sprite Scale Restoration**:
   - *Root Cause Analysis*: In `src/main.cpp`, under `SCENE_LADDER_CLIMB` rendering, `modelHero` was calculated via `glm::translate` and immediately rendered via `gameRenderer.drawQuad()`. Unlike the platformer runner and sky-fall scene, the model scale transformation `glm::scale(modelHero, glm::vec3(playerRenderSize.x, playerRenderSize.y, 1.0f))` was completely omitted. As a result, the hero was rendered onto a default $1.0\times 1.0$ meter quad ($5.5\times$ smaller than normal), causing the player to appear miniature.
   - *Resolution*: Added `modelHero = glm::scale(modelHero, glm::vec3(playerRenderSize.x, playerRenderSize.y, 1.0f));`, restoring the Samurai Mack climbing sprite to $5.5\times 5.5$ meters, perfectly uniform across all scenes.

2. **Post-Intro Tutorial Window Modal**:
   - *Modal Architecture & State Management*:
     - Added `showTutorialModal`, `hasShownInitialTutorial`, and `tutorialOpenedFromPause`.
     - When the intro video finishes naturally or is skipped via Space/Enter/Esc, if `!hasShownInitialTutorial`, `showTutorialModal = true; hasShownInitialTutorial = true; tutorialOpenedFromPause = false;`.
     - While `showTutorialModal` is active, `processInput` captures inputs exclusively (Space, Enter, Esc, or T dismisses the modal), preventing accidental jumps or slides.
     - When opened from the Pause Menu via `[T]`, `tutorialOpenedFromPause = true`, and dismissing returns the game state directly to `STATE_PAUSED`.
     - Updated Pause Menu key list to explicitly advertise `[T]             TUTORIAL / HOW TO PLAY`.
   - *Content & Aesthetics*:
     - Glassmorphic modal with translucent backdrop and radiant cyan/gold header bar.
     - Displays required text explaining "Wandering": *"Endless runner with traps to avoid and shields to pickup. Change movement direction and find the end goal of this venture."*
     - Instructs players to check the Pause Menu for control details and press `T` while in the Pause Menu to view the tutorial window again.
     - Includes a concise control summary and pulsing dismissal prompt.

3. **Dedicated Shield Pickup Icon**:
   - *Eliminated Fruit Ambiguity*: Previously, fruit sprites from `assets/fruit.png` were repurposed to grant defensive shields, creating confusion with direction relics and player goals.
   - *Procedural Texture Generation*: Created `build/gen_shield.py` using standard Python `zlib` and `struct` to generate `assets/shield_pickup.png` ($256\times 64$, 4 animation frames). Designed a high-contrast heraldic shield featuring an arched top, tapered apex, golden outer bevel, sapphire inner gradient, glowing central star emblem, and radial cyan energy halo.
   - *Texture Mapping & Notifications*: Added `getShieldUV(int frame = 0)` in `include/Common.h` with `dv = 1.0f`. Updated texture binding in `src/main.cpp` and rebranded all floating text and corner notifications: `"+10s ENERGY SHIELD!"` and `"ENERGY SHIELD EQUIPPED [Absorbs 1 hazard hit!]"`.

4. **Scene Pacing, Countdown Timers & Exit Announcements**:
   - *Problem*: In `SCENE_LADDER_CLIMB` and `SCENE_SKY_FALL`, the 15-second survival trial lacked visual progression, and directional exit relics appeared abruptly without warning.

     - Added a real-time top-center countdown badge (`SURVIVE UNTIL EXIT: XX.Xs`) featuring a glassmorphic background and cyan-to-gold countdown progress bar.
     - Added `exitAppearedBannerTimer` state variable. When `scenePlayTime >= SCENE_DIRECTION_COOLDOWN` (15.0s), triggers `audioMgr.play(SFX_RELIC)` and displays an announcement banner at top-center:
       `=== EXIT APPEARED! ===`
       `TOUCH A DIRECTION ARROW TO RETURN`
     - Positioned directional arrow relics visibly ahead along the climb/descent lanes (ladder: $+5.2\text{m}, +8.2\text{m}, +11.8\text{m}$; sky-fall: $-6.5\text{m}, -12.0\text{m}, -17.5\text{m}$), giving players ample visual warning to plan and execute their exit maneuver.
