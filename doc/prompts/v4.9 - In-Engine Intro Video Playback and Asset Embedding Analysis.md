> 2. **Evaluation of In-Engine Video Playback Architecture:**
>    - The project uses Modern OpenGL 3.3 Core Profile with GLFW on Windows (MinGW-w64).
>    - To play MP4 video in-engine without third-party external dependencies (e.g., without requiring users to install FFmpeg or heavy DLLs), we utilized native **Windows Media Foundation** (`IMFSourceReader`, `-lmfplat -lmfreadwrite -lmfuuid -lole32`), available out of the box on all modern Windows installations.
>    - Decoded video frames are read as `MFVideoFormat_RGB32` (or `GL_BGRA`), dynamic OpenGL 2D texture allocated, and uploaded on the fly via `glTexSubImage2D`.
>    - Decoded audio stream: extracted as 16-bit PCM Wave data into in-memory buffer and played synchronously via Windows `PlaySoundA(SND_MEMORY | SND_ASYNC)`.
>    - Created state `STATE_INTRO_VIDEO = 0` in `GameState`. On launch, game enters intro video playback; user can watch the full 15s or press `Space`, `Enter`, or `Esc` to skip directly to game start.
>
> 3. **Asset Embedding & Binary Size Reduction Technical Analysis:**
>    - *Can it be embedded into game files?*
>      **Yes.** Two primary methods exist on Windows:
>      1. Windows Resource Script (`.rc`) compiled via GNU `windres` into a `.res`/`.o` COFF object and linked into `main.exe`. Accessible at runtime via `FindResource` / `LoadResource` / `LockResource`.
>      2. Compile-time byte array: A tool converts the binary MP4 into a C++ header (`const unsigned char introVidData[] = { 0x00, 0x00, ... };`).
>    - *Will embedding reduce its size?*
>      **No.** An MP4 video encoded with H.264/AAC is already heavily compressed using lossy temporal inter-frame prediction, Discrete Cosine Transform (DCT), and CABAC/Huffman entropy coding. Embedding an MP4 file into the `.exe` places those exact compressed bytes into the executable's `.rsrc` or `.rodata` section without further compression. In fact, compiling as a C++ source byte array increases the compiler object file size significantly during build time.
>      Real file size reduction requires video transcoding (e.g., downscaling to 720p or re-encoding at ~900 kbps, which reduces the file from ~4.6 MB to ~1.4 MB).
